# Circle AI — Спецификация сессии компаньона

Данный документ определяет **контракт жизненного цикла ICompanionSession**, который должны
реализовывать все языковые порты. `ICompanionSession` — это основная поверхность API,
с которой взаимодействуют хост-приложения (MAUI, Android, iOS, Web, HarmonyOS).

---

## 1. Концепции

### 1.1 Сессия

`ICompanionSession` представляет **единую непрерывную беседу** между одним
пользователем и B!. Она охватывает период от создания (первое сообщение) до завершения
(пользователь закрывает приложение или сессия явно завершается).

Сессии **не сохраняются сами по себе** — сохраняются только история `CompanionTurn` и
лежащие в основе `AffectState`/`PersonaState`. Новая сессия, созданная на следующий день,
подхватывает то же состояние аффекта и персоны из хранилищ.

### 1.2 Контекст

`CompanionContext` содержит всё необходимое, чтобы B! оставался в контексте:

| Поле | Назначение |
|-------|---------|
| `UserId` | Пользователь, которому принадлежит сессия |
| `AppContext` | Вызывающее приложение (например, `"tgn.bidbaas"`, `"tgn.tagme"`) |
| `Interface` | Способ отображения ответа (голос, часы, текст…) |
| `Locale` | Язык ответов (переопределение) |
| `Affect` | Текущее эмоциональное состояние B! для данного пользователя |
| `Persona` | Усвоенный стиль B! для данного пользователя |
| `ActiveGoals` | Цели, в достижении которых B! должен активно помогать |

### 1.3 Формирование ответа в зависимости от интерфейса

Перечисление `InterfaceKind` определяет длину и стиль вывода:

| Значение | Подразумеваемое ограничение |
|-------|--------------------|
| `Text` | По умолчанию — без специальных ограничений |
| `Voice` | Короткие предложения, без разметки markdown, без списков |
| `Watch` | Максимум ~40 слов; предпочтительно одно предложение |
| `Car` | Очень коротко; без списков; безопасно для использования без взгляда на экран |
| `Tv` | Разговорный стиль; кратко; без блоков кода |
| `Ar` | Ультракороткие оверлеи (≤ 15 слов) |
| `Iot` | Одна фраза-действие |

Реализациям рекомендуется добавлять в системный промпт инструкции,
соответствующие типу интерфейса.

## 2. Жизненный цикл сессии

```
┌──────────────────────────────────────────────┐
│                                              │
│  1. Create session with CompanionContext      │
│                                              │
│  2. User sends a message                     │
│     a. SendAsync(text)     → CompanionTurn   │
│     b. StreamAsync(text)   → token stream    │
│                                              │
│  3. Optionally: user sends feedback          │
│     SignalFeedbackAsync(Positive|Negative)   │
│                                              │
│  4. B! may raise ProactiveMessageReady event │
│     at any time (background thread is fine)  │
│                                              │
│  5. Dispose the session when done            │
│                                              │
└──────────────────────────────────────────────┘
```

---

## 3. Контракт интерфейса

### 3.1 `SendAsync(userMessage)`

Блокирующая (ожидаемая) операция отправки-получения. Добавляет поворот в `History`.

**Предусловия:**
- `userMessage` не должен быть null или пустым.

**Постусловия:**
- `History.Count` увеличивается на 1.
- `AffectState` обновляется внутри сессии (точное время — на усмотрение реализации,
  но это должно произойти до возврата следующего вызова `GetContext()`).
- Возвращаемое `CompanionTurn.UsedTools` равно `true`, если в процессе генерации
  происходили вызовы `IToolBridge`.

### 3.2 `StreamAsync(userMessage)`

Потоковая передача токен за токеном. **История обновляется** после сборки полного
ответа (то есть после завершения потока), а не в процессе.

Возвращаемый асинхронный поток выдаёт **частичные токены** — вызывающий код должен
их конкатенировать.

### 3.3 `AgentAsync(task, tools?)`

Выполняет многошаговый агентный цикл: модель вызывает инструменты и рассуждает
до получения окончательного ответа. Возвращает итоговый текстовый ответ.

Если `tools` равен null или пуст, метод деградирует до одного вызова `GenerateAsync`
(без цикла инструментов).

### 3.4 `GetContext()`

Возвращает **текущий** `CompanionContext`, включая актуальные `AffectState` и
`PersonaState`. Может быть вызван в любое время; не зависит от незавершённых
асинхронных вызовов.

### 3.5 `SignalFeedbackAsync(polarity, correction?)`

Записывает обратную связь пользователя для **последнего поворота** в `History`.

- `FeedbackPolarity.Positive` → вызывает `AffectState.ApplyPositiveSignal()` и сохраняет
- `FeedbackPolarity.Negative` → вызывает `AffectState.ApplyNegativeSignal()` и сохраняет
- `FeedbackPolarity.Correction` → записывает исправление; мутация аффекта не производится

Если `History` пуста (ни одного поворота), метод не выполняет никаких действий.

### 3.6 Событие `ProactiveMessageReady`

Генерируется, когда у B! есть сообщение для проактивной доставки (напоминание,
подсказка по цели и т. д.). Событие **не** добавляет элемент в `History` автоматически —
хост должен вызвать `SendAsync` или иным способом представить сообщение.

## 4. Поля `CompanionTurn`

```
CompanionTurn {
  UserText:      string         // the user's input (verbatim)
  AssistantText: string         // B!'s complete response
  CreatedAt:     datetime (UTC) // timestamp of the assistant's response
  UsedTools:     bool           // true if any tool invocations occurred
}
```

## 5. Обработка ошибок

| Условие | Ожидаемое поведение |
|-----------|--------------------|
| `IChatGenerator` недоступен | Бросить `GeneratorUnavailableException` (или языковой эквивалент) |
| Вызов инструмента завершился с ошибкой | `ToolResult.Success = false`; включить ошибку в контекст; продолжить цикл |
| Встраивание недоступно | Сохранить `EpisodicMemoryEntry.Embedding = null`; не завершать с ошибкой |
| Запись в `AffectStore` завершилась с ошибкой | Записать в лог и продолжить; не передавать вызывающему коду |

## 6. Минимально жизнеспособная реализация (тестирование)

Для модульных тестов и языковых портов, у которых пока нет реального LLM-бэкенда:

```
MockChatGenerator:
  GenerateAsync(messages) → "Mock response from B!"
  StreamAsync(messages) → async stream of ["Mock", " ", "response", " ", "from", " ", "B!"]
```

Тесты сессии компаньона в `tests/` используют `MockChatGenerator` для проверки
жизненного цикла сессии, управления историей, маршрутизации обратной связи и
мутаций аффекта без необходимости реальной модели.

---

## 7. Порядок сборки системного промпта

Референсная реализация на C# собирает системный промпт в следующем порядке:

1. Базовый системный промпт (жёстко заданная персона: «You are B!, the on-device assistant…»)
2. `AffectState.ToSystemPromptHint()` — добавляется, если не пустой
3. `PersonaState.ToSystemPromptHint()` — добавляется, если не пустой
4. Ограничения `InterfaceKind` — добавляются по необходимости
5. Инструкции `AppContext` — необязательные, внедряются хост-приложением

Реализации вправе менять этот порядок при условии прохождения fixture-тестов.
